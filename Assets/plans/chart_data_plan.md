- 프로젝트: music_game (Unity 6.6, C#, URP, Mono, Input System)
- 대상: PLAN.md 2-2. 플레이 안정성 및 데이터 구조 / 4. 채보 데이터 관리
- 목적: 지금 채보들을 검사·분석하고, 새 곡·난이도를 넣을 때 채보 오류를 미리 찾을 수 있게 한다. 채보 형식(`시각,레인[,종료시각]`)과 플레이 방식은 그대로.
- 상태: 구현 완료(2026-11-17) / 사용자 확인 대기 (Tools > Validate Charts 메뉴 사용)
- 작성 경위: GPT가 만든 작업 프롬프트(사용자 제공, 2026-11-17)를 로컬 소스·채보·에셋과 대조해 작성.
- 이 문서는 개발 진행에 따라 수정한다. 작업 범위 확대는 사용자 확인 후 반영한다.

### 요구사항 (사용자 프롬프트 기준)
- 검사 항목: ① 채보 파일·TextAsset 참조, ② 줄 형식·숫자 변환, ③ 시각 ≥ 0, ④ 레인 0~3, ⑤ 롱노트 종료 > 시작, ⑥ 같은 레인 같은 시각 중복, ⑦ 같은 레인에서 롱노트와 다른 노트 겹침, ⑧ 음원 길이 초과, ⑨ 빈 채보·읽을 수 있는 노트 0개, ⑩ 곡·난이도별 채보 참조 누락
- 결과에 파일명·줄 번호·오류 종류·원인이 나와야 한다. 다른 레인의 같은 시각(동시치기)은 정상.
- 분석 항목: 전체·일반·롱노트 수, 동시 입력 수, 첫 노트 시각, 마지막 노트 종료 시각, 채보 길이.
- 기존 동작(잘못된 줄은 경고 후 건너뛰기)·채보 9개·음원·SongData 연결·판정·틱·점수·랭크·플레이 기록은 그대로.
- 기존 채보에서 오류가 나오면 고치지 않고 보고만 한다.

### 제외 범위
- 채보 에디터, 새 채보 형식·변환, BPM 분석·자동 채보 생성, 자동 수정, 새 곡·난이도, UI/UX 변경, 대규모 리팩터링

## 2. 기존 코드 분석 (로컬 확인 2026-11-17)
- **ChartLoader.Load(TextAsset, laneCount)**: 줄마다 `,`로 나눠 칸 수 2·3, 시각·레인·종료시각 숫자 변환(InvariantCulture), `시각 ≥ 0`, `0 ≤ 레인 < laneCount`, `종료 > 시작`을 확인한다. 틀린 줄은 `Debug.LogWarning("… N번째 줄을 건너뜁니다")` 후 건너뛰고, 나머지를 시각순 정렬해 돌려준다. chart가 null이면 경고 후 빈 목록. → 검사 ②~⑤는 이미 하고 있으나 **줄 번호·원인을 모아서 돌려주지는 않는다**. ⑥⑦⑧은 검사하지 않는다.
- **NoteData**: `Time`, `Lane`, `EndTime`(일반 노트 0), `IsLong`(EndTime > Time).
- **사용처**: GameplayManager.Start(플레이 채보, `ChartDuration` = 마지막 노트 종료 시각), SongSelectScreen.RefreshInfo(NOTES = 노트 수, LENGTH = 마지막 노트 종료 시각을 올림한 m:ss, 노트 0개면 START 비활성 + CANNOT PLAY).
- **SongData**: `GetChart(Difficulty)` — 난이도 채보가 하나라도 있으면(`HasDifficulties`) 그 난이도 채보(없으면 null), 아니면 `chart`. Test Song 1~3은 `chart` 하나. SongList에 5곡.
- **판정 동작 (겹침 경계를 정하는 근거)**:
  - 키를 누르면 그 레인의 **대기 중** 노트 중 시간 차가 가장 작은 것을 판정, Good(±0.15초) 밖이면 무시. 유지 중인 롱노트는 후보에서 빠진다.
  - 롱노트 유지 중에는 키를 계속 누르고 있어야 하고, 종료 0.15초 전보다 일찍 떼면 끝 Miss.
  - → 같은 레인에서 **롱노트 종료 시각 이하에 시작하는 노트는 키를 다시 누를 수 없어 칠 수 없다**(겹침 = 오류). 종료 직후 노트도 간격이 매우 짧으면 떼고 다시 누르기 어렵다(경고).
  - 같은 레인 같은 시각의 두 노트는 한 번 누르면 하나만 판정되어 나머지는 Miss(중복 = 오류).
- **음원보다 긴 채보 (분석상 위험)**: 음악이 있는 곡은 곡 시간 = `audioSource.time − 오프셋`인데, 음악이 끝나면 `time`이 0으로 돌아간다. 그러면 음원 길이 뒤의 노트는 판정·Miss 처리가 되지 않고(`IsFinished` false), 결과 전환은 `IsFinished && IsMusicFinished`를 기다리므로 **결과 화면으로 넘어가지 못할 수 있다**. (코드 분석 결과이며 실행 확인은 테스트 CD-09에서)
- **현재 채보 9개 사전 점검 (Python으로 같은 규칙 적용, 파일 변경 없음)**:

| 채보 | 노트 | 형식 오류 줄 | 같은 레인 겹침·중복 | 같은 레인 간격 0.1초 미만 | 마지막 종료 |
|---|---|---|---|---|---|
| kick_easy / kick_chart / kick_hard | 83 / 200 / 377 | 0 | 0 | 0 | 88.71초 (음원 90.6초) |
| huimang_easy / huimang_normal / huimang_chart | 259 / 560 / 950 | 0 | 0 | 0 | 254.65 / 254.65 / 255.73초 (음원 258.25초) |
| test_chart / test_chart_2 / test_chart_3 | 20 / 7 / 8 | 0 | 0 | 0 | 12.5 / 5.0 / 6.0초 (음원 없음) |

  → 지금 채보에서는 오류가 나오지 않을 것으로 예상(구현 후 Unity 검사기로 다시 확인).

## 3. 작업 범위 및 수정 대상 파일
### 3.1 방식 제안
- **검사기는 에디터 전용 메뉴**(`Tools > Validate Charts`)로 만든다. SongList의 모든 곡·난이도 채보를 검사해 Console에 곡/난이도/파일별 요약과 문제(파일명·줄 번호·종류·원인)를 출력한다. 게임 빌드에는 들어가지 않고, 플레이 동작은 바뀌지 않는다.
- **줄 해석은 ChartLoader와 같은 코드를 쓴다**: ChartLoader 안의 한 줄 검사 부분을 `TryParseLine`으로 떼어 내 `Load`와 검사기가 함께 쓴다. `Load`의 결과·경고 문구·동작은 그대로(같은 줄을 같은 이유로 건너뜀). 규칙이 두 곳에 따로 있어 어긋나는 것을 막기 위해서다.
- 분석 수치(노트 수·길이 등)는 `ChartLoader.Load` 결과로 검사기에서 계산한다. 곡 선택 화면의 NOTES·LENGTH 계산은 몇 줄뿐이고 UI 표시용이라 그대로 둔다(공통 함수로 묶는 리팩터링은 하지 않음).

### 3.2 오류 등급 (구현 전 보고 항목)
| 등급 | 뜻 | 해당 검사 | 지금 게임 동작 |
|---|---|---|---|
| **치명(플레이 불가)** | 이 채보로는 플레이할 수 없음 | ① 참조된 채보 파일이 없음(null), ⑨ 읽을 수 있는 노트 0개, ⑩ 난이도 곡인데 세 칸 모두 비었거나 단일 곡인데 `chart`가 없음, ⑧ 노트가 음원 길이 이후(결과로 넘어가지 못할 위험) | ①⑨⑩: 이미 곡 선택에서 START 비활성 + CANNOT PLAY. ⑧: 막지 않음 |
| **오류(일부 노트 제외)** | 그 줄만 빠지고 나머지로 플레이 | ② 형식·숫자, ③ 음수 시각, ④ 레인 범위, ⑤ 롱노트 종료 ≤ 시작 | ChartLoader가 경고 후 그 줄 건너뜀 (그대로 유지) |
| **오류(칠 수 없는 노트)** | 읽히지만 실제로 칠 수 없음 → Miss가 됨 | ⑥ 같은 레인 같은 시각 중복, ⑦ 같은 레인에서 롱노트 종료 시각 이하에 시작하는 노트 | 그대로 읽어서 플레이 (해당 노트는 Miss) |
| **경고(수정 권장)** | 플레이는 되지만 확인 권장 | 같은 레인 노트 간격(롱노트는 종료부터) 0.1초 미만, 노트 종료가 음원 끝 1초 이내, 난이도 곡에서 일부 난이도만 비어 있음(그 난이도는 START 비활성) | 영향 없음 |

### 3.3 사용자 결정 (2026-11-17, 추천안 확정)
1. **게임 중 차단 안 함**: 게임 동작은 바꾸지 않고 검사기로 알려 주기만 한다. 칠 수 없는 노트·음원 길이 초과 채보를 곡 선택에서 막는 것은 이번 범위가 아니다(필요하면 별도 승인).

3. **경고 기준값**: 같은 레인 간격(롱노트는 종료부터) 0.1초 미만, 노트 종료가 음원 끝 1초 이내.

### 4.1 ChartLoader 줄 검사 분리 (동작 동일)
```csharp
// 한 줄을 노트로 바꾼다. 형식·숫자·시각 ≥ 0·레인 범위·롱노트 종료 > 시작을 확인하고, 틀리면 이유를 돌려준다.
// 빈 줄은 hasNote = false, error = null 로 true (건너뜀). Load와 에디터 검사기가 함께 쓴다.
public static bool TryParseLine(string line, int laneCount, out NoteData note, out bool hasNote, out string error) { … }

public static List<NoteData> Load(TextAsset chart, int laneCount)
{
    // … 기존처럼 줄마다 TryParseLine, 실패하면 기존과 같은 경고 문구로 건너뜀, 마지막에 시각순 정렬
}
```
- 오류 이유 문구: "칸 수가 2·3이 아님", "시각이 숫자가 아님", "레인이 정수가 아님", "음수 시각", "레인 범위(0~3) 밖", "종료 시각이 숫자가 아님", "종료 시각이 시작보다 늦지 않음".
- 기존 경고 문구 `ChartLoader: {이름} {N}번째 줄을 건너뜁니다: "…"`는 그대로 두고 끝에 이유만 덧붙이는 것도 가능 — 문구를 바꾸지 않는 안을 기본으로 한다.

### 4.2 ChartValidator (에디터 전용)
```csharp
public enum Severity { Fatal, LineSkipped, Unplayable, Warning }
public class Issue { public Severity Severity; public string File; public int Line; public string Kind; public string Reason; }
public class Stats { public int Total, Tap, Long, ChordTimes; public double First, LastEnd, Length; }

// 채보 1개 검사: 줄 해석(ChartLoader.TryParseLine, 줄 번호 보존) → 같은 레인 정렬 후 중복·겹침·간격 → 음원 길이 → 분석 수치
public static (List<Issue>, Stats) Validate(TextAsset chart, AudioClip music, int laneCount = 4);

[MenuItem("Tools/Validate Charts")]
// SongList의 곡마다: 난이도 곡이면 Easy/Normal/Hard 각각(빈 칸은 경고), 단일 곡이면 chart 하나 → 요약 1줄 + 문제 줄 출력
// 치명·칠 수 없는 노트는 Debug.LogError, 줄 건너뜀·경고는 LogWarning, 요약은 Log
```
- 동시 입력 수 = 같은 시각(소수 4자리 기준)에 노트가 2개 이상인 시각의 수. 채보 길이 = 마지막 노트 종료 − 첫 노트 시각.
- 결과 예: `[kick / Hard] kick_hard.txt — 노트 377 (일반 357, 롱 20), 동시 61곳, 첫 3.43초, 마지막 종료 88.71초, 길이 85.28초 — 문제 없음`

## 7. 검증 결과 및 미해결 사항
- 구현: 계획 4절 그대로. 계획과 다른 점은 `TryParseLine`에 `hasNote` 출력 추가(NoteData가 struct) 하나.
- 검증 방식: 수정 전 Load 결과를 파일로 저장 후 수정 후와 비교, 검사기 메뉴 실행(`ValidateAll`), 메모리 TextAsset으로 오류 종류별 확인(파일 생성 없음), AUTO 3 회귀, 곡 선택 표시 확인.
- 결과: 6절 표대로 모두 통과. 기존 채보 9개에서 오류·경고 0건 → 고칠 채보 없음.
- 실제 메뉴 결과 (Tools > Validate Charts):
  - `ChartValidator: 채보 9개 검사 — 문제 0, 경고 0`
  - 예: `[kick / Hard] kick_hard.txt — 노트 377 (일반 357, 롱 20), 동시 61곳, 첫 3.43초, 마지막 종료 88.71초, 길이 85.29초 — 문제 없음`
- 미해결: 음원 길이를 넘는 노트가 있을 때 게임에서 결과 전환이 실제로 멈추는지는 코드 분석만 했고 실행 확인은 하지 않음(지금 채보는 해당 없음, 검사기가 "치명"으로 알려 줌).
