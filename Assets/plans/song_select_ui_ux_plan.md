# 곡 선택 화면 UI/UX 개선 구현 계획서

## 1. 작업 목적 및 요구사항
- 프로젝트: music_game (Unity 6.6, C#, URP, Mono, Input System)
- 대상: PLAN.md 2-4. UI/UX / 2. 곡 선택 UI/UX
- 목적: 곡 선택 화면의 기능은 그대로 두고, 시각적 완성도와 정보 가독성을 높인다(DJMAX·EZ2ON 같은 PC 리듬게임 곡 선택 화면 참고, 복제하지 않음).
- 상태: 구현 완료(2026-11-17) / 사용자 화면 확인 대기
- 작성 경위: GPT가 만든 작업 프롬프트(사용자 제공, 2026-11-17)를 로컬 소스·씬과 대조하고, 현재 화면을 1920×1080으로 캡처해 작성.
- 이 문서는 개발 진행에 따라 수정한다. 작업 범위 확대는 사용자 확인 후 반영한다.

### 유지할 기능 (변경 없음)
곡 목록·클릭 선택, ↑↓ 곡 이동, Enter 시작, ←→·+/- 배속, Easy/Normal/Hard(마우스만), 난이도별 노트 수·길이, 제목·아티스트, 미리듣기(처음부터 1번, 같은 곡·난이도 변경 시 재시작 없음, 다른 곡이면 교체, 음악 없는 곡 무음), 곡·난이도별 최고 기록(AUTO 제외), SETTINGS 이동, START·CANNOT PLAY, 선택 곡·난이도 유지·복원.

### 개선 대상
| 영역 | 개선 방향 |
|---|---|
| 곡 목록 | 선택 곡을 더 분명하게, 간격·정렬 정리, 긴 제목 가독성, 정보 영역과 구분 |
| 곡 정보 | 제목·아티스트·노트 수·길이의 위치·크기·강조 순서 정리 |
| 난이도 | 세 버튼을 색으로 구분, 선택한 난이도를 확실히 강조 |
| 플레이 기록 | BEST SCORE·RANK·COMBO·NO RECORD를 한 덩어리로 정리 |
| START·SETTINGS·배속 | START 위치·가독성, 플레이 불가 상태, SETTINGS 접근성, 배속 배치 |

### 제외 범위
- 게임플레이·채보·음원·점수·판정·콤보·랭크·기록 저장 구조 변경, 새 곡·난이도, 검색·정렬·필터, 앨범 이미지·배경 영상, 새 패키지·외부 에셋(승인 없이), 애니메이션(별도 결정 전)

- 왼쪽 곡 목록, 오른쪽 정보가 같은 배경 위에 떠 있어 영역 구분이 없다. 오른쪽 정보는 x 1000에 세로로 나열되고, 기록(작은 회색 글자)만 x 1400에 따로 떨어져 있다.

### 2.3 SongSelectScreen.cs 표시 관련 부분
- `Start`: 곡 버튼 복제(이름 `Song{i}`, 세로 `itemSpacing` 110, 내비게이션 끔, 라벨 = 제목), 난이도·START·배속·SETTINGS 버튼 연결.
- `Select`: 곡 버튼 색(`image.color` 선택/기본), 곡이 바뀌면 미리듣기, `RefreshInfo`.
- `RefreshInfo`: 난이도 그룹 표시 여부, 난이도 버튼 색(선택만 난이도 색), 기록 문자열(`recordText`), 채보 → `ShowInfo`.
- `ShowInfo`: 제목·아티스트, `"NOTES  " + 수`, `"LENGTH  m:ss"`, CANNOT PLAY·START 활성.
- `UpdateSpeedText`: `NoteSpeed.Label`("SPEED x5.0").
- 입력(`Update`): ↑↓ 곡, Enter 시작, ←→ 배속. — 이번 작업에서 바꾸지 않는다.

### 2.4 현재 문제점
1. 영역 구분 없음 — 목록·정보·조작이 같은 배경에 흩어져 시선 흐름이 없다.
2. 강조 순서가 약함 — 제목(72)과 노트 수·길이(44)·아티스트(44)의 크기 차이가 작고, 노트 수·길이는 라벨과 값이 같은 크기라 숫자가 눈에 안 들어온다.
3. 기록이 떨어져 있음 — 작은 회색 3줄이 NOTES 옆에 붙어 있어 정보 묶음으로 보이지 않고, 랭크가 강조되지 않는다.
4. 난이도 버튼 — 선택 안 된 두 버튼이 같은 남색이라 어떤 난이도인지 색으로 알 수 없다.
5. 주황 버튼이 많음 — START·SETTINGS·배속 −/+가 모두 같은 주황이라 가장 중요한 START가 돋보이지 않는다.
6. 곡 목록 — 글자가 가운데 정렬·44로 커서 긴 제목이 잘릴 수 있고(현재 곡은 짧아 문제없음), 선택 곡이 색만 다르다.
7. CANNOT PLAY — START 옆 큰 빨간 글자라 배치가 어색하다.

### 4.4 기존 기능과의 연동
- 기존 오브젝트(SongTitle, SongArtist, SongNotes, SongLength, RecordText, DifficultyGroup·버튼, Message, StartButton, SettingsButton, Speed*)는 이름·참조를 그대로 두고 위치·스타일만 바꾼다 → 코드 참조가 끊기지 않는다.
- 새 오브젝트(패널, 구분선, 카드, 라벨, 기록 칸)는 장식이거나 새 직렬화 필드로만 연결한다. 장식 Image는 Raycast Target 끔(곡 버튼·난이도 버튼 클릭을 가리지 않게).
- 패널은 곡 버튼보다 먼저(뒤) 그려지도록 Canvas 순서를 맞춘다.

### 4.5 예상 문제와 해결
| 문제 | 해결 |
|---|---|
| Kanit에 한글이 없음 | Kanit은 숫자·영문 값(점수·콤보·노트 수·길이·랭크)에만, 제목·아티스트는 기존 내장 글꼴 |
| 긴 곡 제목 | Text Best Fit(목록 최소 26, 정보 제목 최소 44), 그래도 넘치면 잘림 대신 줄임 확인 |
| 패널이 버튼 클릭을 가림 | 장식 Image의 Raycast Target 끔, 레이캐스트로 버튼 최상단 확인 |
| 곡이 많아져 목록 패널을 넘침 | 현재 5곡(100 간격 → 500px)로 패널 안에 들어감. 스크롤은 요청 범위 밖 — 8곡을 넘으면 별도 작업으로 보고 |
| Outline이 비활성 버튼에서 어색함 | 비활성 START는 Outline 없이 기본 비활성 색 |

### 4.6 구현 순서
1. 스크립트 표시 코드 수정 → 컴파일
2. 씬: 패널·구분선·카드·라벨·기록 칸 추가, 기존 오브젝트 위치·스타일 변경, 참조 연결
3. 스크린샷(희망 Hard 기록 있음 / kick 기록 없음 / Test Song / CANNOT PLAY) 확인·조정
